# 文本分类置信度与人工独立测试

## 已实现

- 数据看板按省份和预测业务展示提问数、平均模型置信度、最低模型置信度及高置信度（≥0.8）的提问数。
- 只有通过拒识门槛的提问才有可展示的分类置信度。未确定业务的置信度为NULL，不伪造为0或100%；旧结果也保留NULL。
- 模型改用训练标题生成的CountVectorizer词表，再计算TF-IDF和朴素贝叶斯。词表和IDF均不使用提问或人工测试标签。全为生词时不再通过哈希碰撞产生业务特征。
- 无有效特征、训练类别不足两个、训练词汇覆盖率低于0.5、最大类别概率低于0.6或前两类概率差低于0.15时，归为“未确定业务”。高置信度仍可能误判，门槛不是正确率保证。
- 重复课程标题按规范化文本去重，标签冲突的标题不参与训练；训练文本没有有效分词或不足两个类别时，整批提问拒识，性能标记样本不足。

这些改动增强了证据不足时的拒识和结果可检查性。是否提高实际准确率，仍需通过真实人工测试确认。模型概率没有经过校准，不能把90%的模型置信度解释成90%的实际正确率。

## 人工复核

后台菜单“分类人工复核”，或数据看板的“人工复核与独立测试”入口，可以保存、修改、撤销提问标签。类别来自上架课程的顶级业务分类，另提供“未确定业务”。页面按实际Spark逐条结果提供“Spark已分类”和“未确定业务”两个分组，展示预测类别、可用置信度和批次；人工标签独立保存，不会被模型结果自动填写或改变分组。“只看待标注”作用于各分组，分组人数也随此筛选更新。

`V23__question_spark_predictions.sql`新增`analysis_question_prediction`。文本分类任务额外输出`text_classify_detail`，逐条保存提问编号、输入原文SHA256、最终类别及可空置信度，与聚合及评估结果在同一事务替换。新提问、原文变更、来源不匹配及旧批次缺少明细时显示尚未分类提示，不冒充“未确定业务”；需重跑文本分类。只对CSV导出时的制表符和换行替换做相同规范化后校验原文摘要。

展示模型输出可能影响人工判断，因此此复核界面形成的标签不等同于盲测标签。应独立判断而非复制预测，正式效果验收另保留未查看模型输出的独立人工测试集。已有标签仍仅参与独立评估，不参与训练。

复核范围与Spark配置一致：启用用户、real或mock单一来源、最近lookback-days天的提问。记录标注者、标注时间和原始问题；提问原文变化后需要重新标注。系统不自动生成测试真值。

保存和撤销同时校验页面所见原文及复核令牌，后端在事务中锁定对应提问。其他人已保存新标签或题目已修改时，旧页面不能覆盖或删除新结果；需要刷新后重新确认。已有标签的类别退出当前分类体系时，该题重新进入待复核列表。

页面刷新、分页或保存单题时，会保留其他题目尚未提交的选择；仅当题目内容、标签版本或可选类别改变时，清除受影响的选择并提示重新确认。草稿只在当前页面会话内保留，离开页面不持久保存。

建议依次标注页面提供的提问，覆盖实际业务类别、难例及域外提问，避免只挑容易的问题。当前页面以ID散列稳定排序，仍不能保证统计意义上的随机代表性。

## 快照与评估口径

新增`analysis_question_label`保存人工测试标签。`question_labels.csv`包含`id,question,category`，与其余四个业务输入在同一REPEATABLE_READ事务内导出，并一同上传到独立YARN/HDFS批次。没有标签时文件仅有表头；旧CLI快照缺少此文件时仍为未验证。

人工标签仅用于独立测试，不进入训练。Spark只使用当前快照中ID及原始问题内容完全匹配的标签，按规范化问题文本去重。同一文本只从已匹配人工标签的记录中，固定取最小ID的预测作为代表，不让无标签记录或分区顺序影响测试结果。同一文本的冲突标签、已从分类体系移除的标签、与课程训练标题重合的文本不计入测试。规范化包含NFKC、英文大小写统一、空白和标点移除；它不能识别所有语义近重复，人工仍需避免把训练标题改写成测试题。

性能数值的最低报告条件为：模型可训练、至少30条有效独立问题、至少2个明确业务类别、每个已标注类别至少5条（包括标注为“未确定业务”的类别）。这是防止极少样本误导的最低门槛，不能保证样本充分或覆盖全部类别。

样本不足时准确率为NULL并标记`insufficient_data`；没有可用标签时为`unvalidated`。样本充足时输出：

- `accuracy`：全部有效人工测试提问的最终类别准确率。拒识仍在分母；金标为“未确定业务”且模型拒识时算正确。
- `macro_f1`：金标与预测类别并集上的宏平均F1，包括未确定业务。
- `classification_coverage`：给出明确业务类别的测试提问数/全部测试提问数。
- `accepted_accuracy`：只对给出明确业务类别的测试提问计算准确率；需与覆盖率一起阅读。全部拒识时该项为NULL。
- `accuracy_ci95_lower/upper`：二项Wilson 95%准确率区间。这一区间不能消除选样偏差，也不覆盖模型或数据漂移。
- `labeled_test_count`：清理后的有效独立测试问题数，详情中同时记录原始匹配标签数量。

评估结果只适用于当前来源、窗口、模型及已标注样本。模拟数据评估不能代替真实效果；有人工评估也不能直接把地区问答分类量解释为地区居民总体需求。若根据本测试集反复调整模型或门槛，后续结论需要另留未用于调优的新测试数据。

## 部署与使用

1. 构建Spark任务：`mvn -f spark-analysis/pom.xml package -DskipTests`。默认Spark 3.2 API及Java 8字节码，与现有YARN配置一致。
2. 执行`mvn -f backend/pom.xml package -DskipTests`及`npm --prefix frontend run build`。部署并重启后端，Flyway自动执行新增的`V21__text_classification_confidence.sql`和`V22__classification_review_token.sql`；同步部署新版前端并刷新页面。V22为追加迁移，不修改已执行的V21。
3. 在“分类人工复核”中标注提问。系统不会自动替代人工审核。
4. 在“Spark任务”中运行`text_classify`，或运行全部分析。
5. 数据看板查看置信度，Spark任务页查看人工测试准确率、覆盖率和区间。旧批次需要重跑后才有置信度数据，修改标签后也需重跑评估。

本地验证：

```powershell
mvn -f spark-analysis/pom.xml test '-Dspark.version=3.5.1'
mvn -f backend/pom.xml test
npm --prefix frontend run build
npm --prefix frontend run test:classification-review
```

Spark回归包含8任务批次、新增拒识与置信度输出、已知混淆矩阵的指标计算、重复/冲突/训练重合/过期标签剔除及CSV损坏校验。后端用H2验证人工标注范围、迁移SQL、快照导出与结果落库；H2测试提供真实MD5/SHA256函数以适配MySQL内置函数。这些合成数据测试是工程验证，不能当作业务准确率。

2026-10-20优化后验证：Spark共9项测试通过，包含8个任务的批次运行、重复文本在输入倒序和重新分区后的指标稳定性，以及百万行迭代器的分词惰性消费；后端共34项测试，33项通过、1项外部天气测试跳过，覆盖并发首次标注、同秒修改、陈旧页面保存/撤销、原文变化、类别失效和大编号；前端5项草稿行为测试及生产构建通过。未在业务数据库执行V21/V22，未提交真实YARN任务，未生成或替代真实人工标签。
