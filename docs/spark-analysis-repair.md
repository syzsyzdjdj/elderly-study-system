## 统计口径

- `study_time` 是每次上报新增的整数分钟，不是每次上报累计分钟；不能把一条日志当作一次学习会话。
- 热度：窗口内每门课程的独立学习用户数。
- 趋势：每天独立学习用户数及新增分钟之和。
- 分类占比：每个分类去重用户数 / 所有分类去重用户数之和。同一用户可参与多个分类，因此不是互斥人群占比。
- 聚类：活跃天数、活跃日累计分钟的日均值、已接触课程中完成课程的比例；不再过滤单条平均不足5分钟的用户。
- 群体名称改为相对高/低活跃组，不根据这些特征推断连续学习或停学复学。
- 词频改为包含该词的提问条数，同一提问的重复词只计一次，保留 WiFi/APP/12306 等词。
- 无效ID、日期、负时长、越界进度、非法完成状态及完全零行为日志不参与统计。缺失/损坏的输入或输出文件不能当成有效空结果。

## 数据隔离与快照

后端使用 `REPEATABLE_READ` 只读事务导出4个输入文件，整批8个任务复用一次导出；不再逐任务直连 JDBC 获取变化中的数据。

配置默认值：

```yaml
spark:
  data-scope: real  # real 或 mock，禁止混合
  lookback-days: 90
```

`V19__analysis_quality.sql` 增加 `sys_user.is_mock`，回填历史生成器的用户名和昵称组合。新模拟用户显式写入此标记，生成/清理不再按宽泛用户名匹配普通用户。

快照保存在 `spark-tmp/runs/<UUID>/`，包含4个输入CSV、日期窗口/来源/输入行数的 `snapshot.properties` 和本批次结果。远程工作目录和HDFS路径也按UUID隔离。结果不清理旧快照，以便追溯；不自动退出HDFS安全模式。

默认只分析启用用户、上架课程和窗口内数据。默认真实数据较少时，模型可能报告样本不足或任务无法训练，不能为了让任务成功混入模拟数据。

## 原子落库与运行状态

每个任务的结果及评估记录在独立短事务中替换。课程热度和分类占比同时提交。解析或插入失败会回滚，保留旧结果。失败任务的旧批次ID可在任务页识别。

成功但输出为空仍会记录运行时间、批次和来源，避免被显示为“未运行”。批次含失败任务时显示成功/失败数量，不再一律提示“全部成功”。

## 模型评估

- K-Means输出平方欧氏距离轮廓系数；轮廓系数不是业务有效性证明。少于3名用户或无特征差异不强行分组。
- ItemCF与ALS使用全局日期分割：前80%的活跃日期训练，最后20%测试。测试目标是有正反馈（完成或进度≥60）、训练期未接触的课程；仅评估训练期已知用户。未来日志不进入模型和热门基线，冷启动课程保留在测试分母。
- 输出微平均Recall@5、Precision@5（分母=合格用户数×5）、用户覆盖率、热门基线Recall@5及两者差值。
- 测试至少3名合格用户、5个正样本及5个活跃日期。不足时输出 `insufficient_data`，不输出伪造的性能数值。
- 推荐排除所有已接触课程，先过滤有效课程再取Top5。ALS按已训练完整目录获取候选，避免固定20候选漏掉剩余课程。
- FP-Growth输出并按提升度排序；默认要求lift>1.05且共学用户数≥5。没有有价值规则时应允许空结果，高置信度不等于强关联。
- 文本分类仍为“课程标题弱监督”的探索模型，未具备人工标注提问测试集，因此准确率标记 `unvalidated`，不得宣称已验证的地区需求。空特征、单类别、低置信度或小类别差距归为未确定业务；置信度阈值不是正确率保证。

## 验证与重跑

在JDK17下：

```powershell
mvn -f spark-analysis/pom.xml test '-Dspark.version=3.5.1'
# 上一步用3.5验证运行；部署jar恢复3.2 API编译及Java8字节码。
mvn -f spark-analysis/pom.xml install -DskipTests
mvn -f backend/pom.xml test
cd frontend
npm run build
```

Spark回归测试会创建独立临时CSV，运行全部8个任务，验证清洗、聚合、空输入、推荐排除和评估输出；测试数据不是业务效果结论。后端使用H2内存数据库验证真实事务回滚，不修改业务数据库。

部署时重启后端使Flyway应用V19，确认Hadoop VM、SSH、HDFS及YARN均可用，再在“Spark分析任务管控”点击“一键运行全部8个任务”。检查各任务批次ID相同、来源正确，并查看评估与失败状态。
