# 首页混合课程推荐

`GET /api/course/recommend` 保持课程数组结构，新增 `recommendationSources` 和 `recommendationReason`。首页、每日提示通过同一个 `AnalysisService.recommendCourses` 入口获取结果，无需修改数据库表或重新训练 Spark 就能使用内容推荐。

## 候选、排序与补位

1. 合并当前用户全部 `study_log` 和 `study_record` 历史，按课程聚合。出现过的课程全部排除，包括低进度、90天以前的课程。进度、完成或时长大于零的记录才作为兴趣种子；下架课程可以作为种子，但不会被推荐。
2. 在上架、未学课程中找内容候选：同分类权重 0.7，同一顶级分类权重 0.35；标题 Jaccard 相似度权重 0.3。标题做 Unicode/大小写规范化，汉字取相邻双字、英文取完整词，过滤“课程、学习、教程”等通用词。无分类关联时标题相似度至少 0.15 才独立生成候选。每个候选取与种子匹配的最高分，并按种子的学习进度加权，原因指向具体学过的课程。这是规则相似度，不是语义模型或准确率。
3. 行为达到运行门槛时，加入当前用户已有的 ALS 和 Item-CF 离线候选。分别过滤已学、下架、重复候选，再做名次融合：`0.6/(10+内容名次) + 0.25/(10+ALS名次) + 0.15/(10+ItemCF名次)`，各路名次从1开始，缺失来源贡献为0。分数相同时按课程ID升序。两种模型独立参与，不会因为 ALS 有无效候选而阻止 Item-CF。名次融合避免不同原始分数的量纲影响；权重是初始业务规则，尚未经过效果调优。
4. 默认最多返回6门。内容和模型候选不足时，按最近90天**真实且启用用户的独立人数**补充热门课程；热度仍不足则按创建时间和ID降序补充最新课程。新课程没有共学记录也能通过内容/最新入口推荐。候选耗尽时返回不足6门或空数组，绝不重新加入已学课程。

内容、模型、热门、最新四类结果均进行去重、已学过滤、上架检查。热门人数从当前学习日志聚合，避免使用过期或模拟热度表。前端不再在推荐为空时自行请求普通课程列表，以免绕过已学过滤。

## 行为门槛和批次要求

默认近90天至少5名真实启用用户、20个去重的正反馈用户课程对（完成或进度≥60），且当前用户至少有2门有效种子课程，才使用协同过滤排序。重复上报、模拟用户、禁用用户、未来日期和窗口外记录不计入门槛。模型还须具有最近30天以内的 `real/completed/snapshot` 元数据，防止旧版、模拟、过期批次进入首页。

这些数字是初始运行策略，**不是推荐效果已经验证的证据**。离线 Recall@5 等评估继续独立计算，`insufficient_data` 不会因热门/内容补位而变成“已验证”。Spark 两个任务仍只输出各自的协同过滤候选，因此任务表中 Item-CF 输出0条时，首页依然可获得内容和热门推荐。

可通过 Spring 配置或对应环境变量调整默认值：

```yaml
recommendation:
  limit: 6
  lookback-days: 90
  min-users: 5
  min-positive-pairs: 20
  min-user-courses: 2
  max-model-age-days: 30
```

## 来源展示

| API 来源值 | 首页标签 | 原因示例 |
| --- | --- | --- |
| `content` | 相似课程 | 与你学过的《微信支付账单》分类相同 |
| `als` | 学习偏好 | 结合相似学习偏好排序 |
| `item_cf` | 共学关联 | 学过相关课程的学员也在学习 |
| `popular` | 热门补充 | 最近90天有2位学员学习 |
| `latest` | 最新课程 | 最新课程补充，供你探索新内容 |

同一课程可能同时拥有多个来源，只显示一张卡片。接口不暴露融合分数为置信度，也不把最新课程标成热门。网络失败与“没有未学候选”使用不同的空状态。

## 验证和生效

`HybridRecommendationServiceTest` 用 H2 执行真实 SQL，覆盖稀疏数据内容推荐、逐条补位、全历史排除、分类层级/标题关联、名次融合与原始分数缩放、批次后新增学习、独立模型回退、模拟/过期批次排除、重复日志不抬高门槛、匿名去重热度及候选耗尽。

更新并重启后端、更新前端构建或刷新开发页面后生效。无需数据库迁移。已有真实 Spark 候选可直接使用；样本不足时优先由内容与补位策略提供覆盖。当前实现按请求读取课程目录并计算内容关联，适合当前的小型课程库；课程规模显著扩大时应预计算内容特征和缓存公共统计，再用线上完整历史做最后过滤。
