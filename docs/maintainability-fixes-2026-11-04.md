# 可维护性修复与验证

2026-11-04。本记录对应同日代码评审后的本地修改，未部署到生产服务器。

## 业务正确性

- 兑换发放/取消以数据库 `WHERE status='PENDING'` 条件更新取得处理权。只有更新成功的事务能够退款，状态、余额、库存和积分明细在同一事务提交；后续失败会回滚，可重试。库存不足通过事务回滚扣分，移除重复补偿代码。
- 奖品保存和兑换处理改用独立 DTO。拒绝负价格、负库存、非法状态和无效处理动作；服务层同时拒绝历史无效价格。零积分奖品仍允许兑换。
- 本地问答修正收款码与付款码的说明，并以不启用大模型的实际服务调用测试验证。同步修正问答优先级和课程删除接口的过时注释。其余内置答案仍需持续人工内容审核。

## 权限与分类

- `shared/admin-navigation.json` 供后端导航服务和前端共用。管理员拥有全部后台入口；课程管理员只能分配课程、分类入口，个人中心始终可用；学员使用学习端。菜单分配控制导航，API 权限继续由后端角色鉴权执行，不把菜单隐藏当作安全边界。
- `/api/menu/mine` 返回当前用户可见菜单。路由和桌面/手机菜单使用同一结果，导航时重新获取，可反映菜单撤销。网络失败取消导航；退出登录期间返回的旧响应不会恢复菜单。
- 角色列表回显实际已分配菜单，保存前校验菜单存在且适用于角色，去重后再写入。不允许通过此页面更改管理员或学员的导航模型。
- 新增 Flyway V27：补齐缺失的导航记录；对尚无任何菜单关联的课程管理员角色初始化课程和分类入口，已有分配保持不变。不会修改账号、课程或学习记录。
- 自动分类规则移至 `backend/src/main/resources/course-category-rules.json`，使用分类名称路径关联数据库当前主键，不依赖种子数据 ID。子分类优先，同层采用最长关键词，修复“微信支付”被“微信”抢先匹配。禁用、缺失、循环或同路径重复的目标不参与匹配。分类重命名时需同步调整规则配置；此实现尚未建设后台规则编辑器。

## 维护成本

- 课程列表批量填充分类与收藏；学习记录、日志和课程学员列表批量填充课程/用户，去掉这些路径的逐条查库。
- 语音预生成使用单工作线程、有界队列（64 项）和同课程排队合并；运行期间发生的更新可以再排一次，任务开始时读取最新内容。队列满时不阻塞保存，记录日志，访问课程时仍可按需生成。
- 积分每日限次保留数据库用户行锁，移除重复且持续增长的进程内锁 Map；两个独立服务实例并发发奖的事务测试验证限次仍生效。
- 分析任务名称、标识和说明收敛到有类型的 `AnalysisTaskType`，批量任务和目录读取同一来源，分派使用枚举。
- 课程卡片与问答整页容器的有效布局收敛到基础样式，删除对应主题覆盖与旧阴影覆盖。其余样式仍可按页面逐步迁移，不宣称已完成全站 CSS 重构。

## 构建与发布

- CI 增加不使用生产签名材料的 Android debug 构建与 lint。
- 常规发布使用完整后端 JAR 和前端 dist，经 `tools/package_server.py` 打包。发布包附 `release-manifest.json`：包含完整制品模式、源码文件指纹、可用时的 Git revision、迁移列表和每个发布文件的 SHA-256；打包后重新核对归档内容，防止构建输入在打包期间变化。没有 Git 元数据时 revision 为 null，源码指纹不能替代源码版本管理。
- 历史局部 JAR 补丁脚本保留用于解释既有部署；不作为本次常规发布路径。
- 源码审计修复 shell 变量引用和明确 `openssl rand -hex` 随机生成语句的误报，仍拒绝任意命令替换中可能存在的硬编码秘密，并有回归测试。

完整制品打包示例（使用当前实际构建路径）：

```powershell
python tools/package_server.py --backend-jar work/maintainability/backend/elderly-study-backend-1.0.0.jar --frontend-dist frontend/dist --output work/maintainability/releases
```

默认包不携带来源待核验媒体；升级时应保留服务器现有媒体目录。前后端需配套发布，新后端启动时执行 V27。回滚前应验证 Flyway 版本兼容，不删除既有业务数据。
