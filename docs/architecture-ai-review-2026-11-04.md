# 可维护性与 AI 能力审查

审查日期：2026-11-04。范围为当前工作区的 Spring Boot、Vue、问答链路、语音与推荐边界、配置及异常处理；不据此推断作者或“AI生成代码比例”。

## 结论

系统有清晰的 Controller / Service / Mapper 分层、Flyway 迁移、角色授权和回归测试基础，可以继续维护。主要问题是产品功能与运行条件没有充分区分、若干类承担过多职责，以及规则内容与流程代码混在一起。当前不宜把它描述成具备实时检索与自动办事能力的 AI Agent。

问答实现是“人工维护 FAQ 匹配 → 可选 DeepSeek → 本地关键词兜底”。FAQ 和本地规则不等于模型推理，也不等于带出处的知识检索。本次增加了有界多轮上下文和来源提示，但未引入向量检索、网页搜索或自动执行操作。

## 本次已修复

| 问题及影响 | 实施的改动 | 验证方式 |
| --- | --- | --- |
| 模型每次只接收当前一句，无法可靠理解“广州”等追问 | 请求支持最近6条已完成消息；每条最多1000字，仅接受 user / assistant。系统提示由服务器提供 | 模拟真实 HTTP 消息体检查历史顺序、当前问题位置；非法角色和超限请求测试 |
| 本地回答依赖代码顺序，泛化词抢占具体意图 | 27条现有回答移到 local-qa.json；反诈条目优先，具体词优先，泛化词降权；支持大小写及全角归一化 | 视频洗钱、火车票APP、打车APP、12306预约、WiFi、英文词边界回归 |
| 本地兜底与模型回答没有明显区别，人工审核内容被称为“官方解答” | 单独标注人工审核、模型生成、本地知识库；解释模型关闭、未配置和调用失败三种降级原因 | 服务路由与前端响应契约测试 |
| 前端默认20秒超时，后端模型请求可能等待15秒连接+60秒读取 | 聊天请求默认90秒；组件销毁时取消浏览器等待，统一忽略主动取消的网络错误 | 前端构建、既有取消测试及调用路径检查；取消浏览器请求不保证已发出的供应商推理停止 |
| 问题长度与客户端历史缺少约束 | 问题最多1000字、历史最多6条、单条最多1000字；禁止客户端传入 system 角色 | Bean Validation 与供应商调用前防御校验 |
| 配置刷新先清空缓存，运行开关与密钥可能短暂回退到默认值 | 构建完整缓存后一次发布，配置写入与刷新共用互斥锁 | 全量后端回归；不声称批量数据库保存已成为跨实例原子事务 |
| 缺失图片被万能异常处理成HTTP200+系统错误 | 静态资源缺失改为HTTP404，不再记录为未知系统故障 | 发布后的公开缺失资源请求核对 |
| 日志可能包含问题正文或供应商异常响应 | FAQ日志只记录条目ID；供应商失败记录异常类型，避免记录其响应正文 | 代码检查 |

## AI 能力边界

| 能力 | 当前实现及限制 |
| --- | --- |
| 对话 | 可选外部模型；本次支持当前页面的最近6条历史，不自动读取数据库中的全部聊天历史或用户资料 |
| 知识库 | 人工 FAQ 与本地关键词规则；没有向量检索、相关段落引用或答案来源核验 |
| 实时信息 | 问答没有联网检索工具；提示词要求不冒充实时天气或最新政策查询，缺少必要条件先澄清 |
| 推荐 | 分类/标题/行为数据和 Spark 结果的混合排序，有数据不足时的补位；不应与大语言模型推理混称 |
| 语音 | 合成模式取决于部署；仅录音/设备朗读模式不能生成外部音色。此能力边界已由此前的语音报错修复明确显示 |
| 自动执行 | 未提供替用户办理业务、执行支付或修改外部账户的 Agent 工具 |

## 后续优先事项

1. **高优先：模型调用配额与故障隔离。** 当前问答没有独立的按用户计费配额、并发限额与熔断策略；问题长度约束不能代替成本控制。应先确定真实用户量、预算和供应商限制，再引入持久化配额与可观测指标。
2. **高优先：审核知识的事实有效期。** 移出的27条回答保留原文，其中含地区、政策时限和操作入口等易变信息。需要维护适用地区、来源、核对日期与失效规则；“人工审核”不等于政府发布。本次未凭推测重写这些事实。
3. **中优先：拆分职责集中的模块。** ChatTtsUtil 约571行，混合多种供应商、进程管理、缓存和文件处理；Dashboard.vue 约690行，混合多组统计与图表。应围绕供应商适配、音频缓存、图表展示分别拆分，保留现有接口并逐步迁移。
4. **中优先：多实例与长期会话。** FAQ缓存与预热进度仍是单进程状态；多实例部署需要配置版本/缓存失效机制。更长会话应先定义会话归属、保留期、删除策略与上下文压缩，不能简单无限追加历史。
